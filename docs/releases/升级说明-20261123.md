# District 360 离线服务器升级说明（2026-11-23）

升级包：`district360-upgrade-202611231449.tar.gz`（代码版本 `6b7b257`）
SHA-256：`489ae00266f414ccb7886a49b29ebfb3423c13a306e3a7339d44d722f55d11ff`

## 这次升级的内容

- **地图点击详情**：选中区后，点击地块、建筑、学校、医疗点会弹出详情卡片。
- **统计库迁移 V9**：给 `map_plot`、`map_building`、`map_poi` 三张表各加一列 `attrs`。只加列，不清表、不改已有数据，后端启动时自动执行。
- **makani 抽取多读一些源字段**：详情卡片里显示的就是这些字段。
- 只替换 `jar/` 和 `static/`。`config/`、`.env` 都不用改，源库地址保持离线服务器自己的配置。

## 第 1 步：检查 makani 源库字段（升级前必做）

新版 makani 抽取会多读五十多个源字段。离线环境的 makani 库如果缺字段或类型不一样，抽取会失败。

1. 打开 `check-makani-columns.sql`，按 `config/application-prod.yml` 里 `d360.makani` 的 `schema` 和 `table-prefix` 两项，改文件开头 `params` 里的值。生产库一般是 `public` 和空串，和文件里的默认值相同。
2. 在离线环境的 **makani 源库**里执行这个文件（psql 或 Navicat 都可以）。

- **结果为空**：全部通过，可以继续。
- **有结果**：先不要升级，把结果发给开发。

## 第 2 步：备份当前版本

在部署目录（`docker-compose.yml`、`start.sh` 所在的目录）执行：

```bash
cp -p jar/district360.jar jar/district360.jar.bak-20261123
cp -a static static.bak-20261123
```

## 第 3 步：替换 jar 和前端并重启

```bash
mkdir -p /tmp/d360-up && tar xzf <升级包路径>/district360-upgrade-202611231449.tar.gz -C /tmp/d360-up
cp /tmp/d360-up/district360/jar/district360.jar jar/district360.jar
find static -mindepth 1 -delete && cp -R /tmp/d360-up/district360/static/. static/
docker restart district360
```

## 第 4 步：确认启动成功

```bash
./start.sh logs        # 或 tail -f logs/district360.log，Ctrl+C 退出
```

日志里应能看到以下两行：

- `Successfully applied 1 migration to schema "stat", now at version v9`：V9 迁移已执行。
- `Started District360Application`：程序已启动。

约 1 分钟后，`docker ps --filter name=district360` 的状态应显示 `(healthy)`。

## 第 5 步：重新抽取一次 makani（详情字段才会有值）

V9 只加列，已有数据的 `attrs` 都是空的。要重新抽取一次 makani，详情才有内容。有两种方式：

- **手动触发**（推荐）。需要 `config/application-prod.yml` 里配置了 `d360.admin.token`：

  ```bash
  curl -m 900 -X POST -H "X-Admin-Token: <口令>" http://127.0.0.1:8360/district360/api/v1/admin/etl/makani
  ```

  约 1.5~2.5 分钟后返回，结果里的 `"status": "success"` 表示成功。
- **等定时抽取**：每天 03:00（迪拜时间）自动执行。

抽取在一个事务里整批替换，抽取期间页面照常可用。

## 第 6 步：验证

```bash
curl -s http://127.0.0.1:8360/district360/api/v1/meta
```

- 在 `/meta` 的返回里，`makani` 的 `lastStatus` 应为 `success`，`lastFinishedAt` 应为刚才的时间。
- 打开页面，选中一个区，放大后点一栋建筑，应弹出详情卡片（高度、层数、用途、所在地块等）。
- 在面板「公共设施」里点学校或医疗的数字，再点列表里的一项，卡片里应显示课程、学生数、专科、床位等字段。

## 回滚

```bash
cp -p jar/district360.jar.bak-20261123 jar/district360.jar
find static -mindepth 1 -delete && cp -R static.bak-20261123/. static/
docker restart district360
```

统计库不用回滚：旧版程序不读 `attrs` 列，Flyway 也会忽略比自己新的 V9 迁移记录。

## 常见问题

| 现象 | 原因和处理 |
|---|---|
| `/meta` 里 makani 的 `lastStatus = failed`，`lastMessage` 提示 `column ... does not exist` | 源库缺字段，第 1 步的检查没做或没通过。页面仍显示上次的数据，只是没有详情。把报错发给开发 |
| 页面能打开但点建筑没反应 | 浏览器缓存了旧前端，强制刷新（Ctrl+F5）。确认 `static/assets/` 下是 `index-pzs5GqEy.js` |
| 卡片弹出但只有标题、显示「源表里没有更多信息」 | 还没重新抽取 makani，做第 5 步 |
