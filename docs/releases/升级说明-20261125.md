## 这次升级的内容

- **V1.0 空间下钻接口** `/api/v2/space/*`：酋长国 → 市政 → 区域 → 社区 → 地块 → 建筑 → 楼层 → 单元，供新前端 `frontend-360` 使用。原 `/api/v1` 接口与现有页面不变。
- **ODS 抽取工程 `d360-ods`**：新增数据源 `d360.datasource.ods`，两个抽取器：
  - `ods-spatial`：全量同步空间下钻 7 张表，参加每日 03:00 定时抽取；
  - `ods-units`：只同步单元表，仅手动触发。
- **统计库迁移 V10–V13**：新建 `theme` schema（空间表 + 业务主题表）、BDMS 编号加市政、地块管控字段加宽。
  101 上的 `district360` 库**已经执行过** V10–V13（开发验证时），升级后日志会显示 `Schema "stat" is up to date`，属正常。
- 主题库 `theme` 里**已有**一次全量同步的数据（地块 41 万、建筑 50 万、楼层 46 万、单元 67 万），升级后接口即可用，不必先抽取。
- 只替换 `jar/`；**需要改 `config/application-prod.yml`**（加 ODS 数据源，见第 3 步）。`static/`、`.env` 不动。

## 第 1 步：检查 ODS 源库字段（只读）

在 111 的 `makani_1119` 库执行 `deploy/docker/check-ods-columns.sql`（`params` 默认 `ods` / `ods_`）。结果为空才继续。2026-11-25 已在 makani_1119 上执行，结果为空。

## 第 2 步：备份

```bash
cd /root/district360
D=$(date +%Y%m%d)
cp -p jar/district360.jar jar/district360.jar.bak-$D
cp -p config/application-prod.yml config/application-prod.yml.bak-$D
sha256sum jar/district360.jar      # 记下升级前线上 jar 的 SHA-256
```

## 第 3 步：配置加 ODS 数据源

编辑 `config/application-prod.yml`，在 `d360.datasource` 下（与 `makani`、`liveability`、`adrec` 同级，缩进 4 格）加：

```yaml
    # ODS 源库（V1.0 主题库抽取用，只读）
    ods:
      url: jdbc:postgresql://10.255.254.111:15432/makani_1119?currentSchema=ods,public
      username: <用户名>
      password: "<密码>"
```

账号与同在 111 上的 makani / 宜居源库相同。不加这段：v2 接口照常可用（读主题库已有数据），只是没有 ODS 抽取器，主题库不会更新。

## 第 4 步：替换 jar 并重启

```bash
mkdir -p /tmp/d360-up && tar xzf <升级包路径>/district360-upgrade-202611251947.tar.gz -C /tmp/d360-up --no-same-owner
cp /tmp/d360-up/district360/jar/district360.jar jar/district360.jar
docker restart district360
```

## 第 5 步：确认启动成功

```bash
./start.sh logs
```

- `Schema "stat" is up to date` 或 `now at version v13`
- `Started District360Application`
- 约 1 分钟后 `docker ps --filter name=district360` 为 `(healthy)`

## 第 7 步（可选）：手动同步

```bash
curl -m 3000 -X POST -H "X-Admin-Token: <口令>" http://127.0.0.1:8360/district360/api/v1/admin/etl/ods-spatial   # 全量，约 15 分钟
```

一个事务整批替换，抽取期间接口照常返回上一次的数据。

## 注意

- **每日 03:00 定时抽取会多跑 `ods-spatial`（约 15 分钟）**。开发机上的后端已关闭定时抽取，避免与 109 同时写同一个库；其他人本地起后端时也请设 `D360_ETL_ENABLED=false`。
- 本次最后两项改动（BDMS 匹配改用临时表、地块按编号挂社区）只做了编译和接口冒烟，**全量同步尚未在新代码上完整跑过**，以首次定时 / 手动同步的结果为准，失败会回滚、不影响已有数据。

## 回滚

```bash
cp -p jar/district360.jar.bak-<日期> jar/district360.jar
cp -p config/application-prod.yml.bak-<日期> config/application-prod.yml
docker restart district360
```
