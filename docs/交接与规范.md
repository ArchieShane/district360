# District 360 · 交接与工程规范

适用对象：接手开发的同事、负责出安装部署包的同事（可以是两个人）。
目的：**开发 → 构建 → 部署**三段分开，每一段有明确的输入、输出和验收标准，换人也能照做。

---

## 1. 角色与边界

| 角色 | 负责 | 产出 | 不做 |
|---|---|---|---|
| 开发 | 改代码、写迁移、更新文档，PR 合入 `main` | 合入 `main` 的提交；发版时打 tag | 不手工打包、不改部署服务器上的文件 |
| 出包 | 按 tag 构建部署包、校验、交付 | `district360-*.tar.gz` + `SHA256SUMS` + 发布说明 | 不改业务代码；发现问题退回开发，不在包里"顺手修" |
| 部署 | 在目标服务器按包内 README 安装 | 运行中的服务 | 不改 jar 内容；配置只改 `config/` 和 `.env` |

**原则：包只能由某个 git tag 构建出来；同一个 tag 重复构建，jar 内容应一致。**

## 3. 开发标准

### 3.1 分支与提交

- `main` 永远可构建、可部署；**不直接 push**，所有改动走 PR。
- 分支名：`feature/<模块>-<简述>`、`fix/<简述>`、`release/<版本>`（仅需要时）。
- 提交信息：`<类型>: <做了什么>`，类型取 `feat / fix / docs / refactor / build / chore`，一次提交只做一件事（沿用现有中文提交风格即可）。
- PR 合入前至少一人 review；PR 描述写清：改了什么、怎么验证、是否含数据库迁移、是否改了配置项。

### 3.2 数据库迁移（Flyway）

- 位置：`backend/d360-stat/src/main/resources/db/migration/`，当前到 `V9`。
- **已合入 `main` 的迁移脚本禁止修改**；要改就新增下一个 `V<n+1>__说明.sql`。
- 迁移要能在**已有数据**的库上执行（线上统计库不会被重建）。
- 迁移只加列、不清表时，PR 描述必须写明"升级后需手动触发一次抽取才有值"（见部署 README）。

### 3.3 配置

- 新增配置项必须同时改三处：`application.yml`（默认值/占位）、`deploy/docker/config/application-prod.yml`（部署模板，写清含义和示例）、README 或本文档的配置说明。
- **任何密码、token、内网账号不得出现在 `application.yml`、`application-prod.yml` 模板和文档里**；模板里用 `<...>` 占位或环境变量。
- 配置项变更要在 PR 里单独标出，出包的人据此写发布说明。

### 3.4 指标口径

- 改取数逻辑必须**同步改** `backend/d360-app/src/main/resources/metric-lineage.yml`（页面悬浮提示读它）。
- 字段口径以与数据治理确认的为准，`docs/District360_数据字段对照_*.xlsx` 仅供参考；口径变更记入 PR 描述。

### 3.5 接口与前端

- 接口字段变更（含新增）要同步 `docs/接口文档.md` 与 `frontend/src/api/types.ts`。**不兼容变更（删字段、改含义）要在 PR 里显式标注。**
- 前端必须通过 `npm run build`（含 `vue-tsc` 类型检查）；依赖版本在 `package.json` 里锁定精确版本，用 `npm ci` 安装。
- 前端使用相对路径打包，不得写死 `/district360`。

### 3.6 合入前自检清单（PR 模板）

- [ ] `mvn -B -DskipTests package` 通过；前端 `npm run build` 通过
- [ ] 本地启动，`/api/v1/meta` 正常，改动涉及的页面区块手动看过
- [ ] 涉及迁移：在带数据的库上跑过
- [ ] 涉及配置：三处模板已同步，无明文密码
- [ ] 涉及指标：`metric-lineage.yml` 已同步
- [ ] 涉及接口：接口文档已同步
- [ ] 源库新增读取的字段：已更新 `deploy/docker/check-makani-columns.sql`（或对应检查脚本）

## 4. 版本与发布标准

### 4.1 版本号

- 语义化版本 `MAJOR.MINOR.PATCH`：
  - MAJOR：不兼容变更（接口破坏、需要重建统计库）
  - MINOR：新功能、新迁移、新配置项（向后兼容）
  - PATCH：仅修 bug
- **一个版本号对应一个 git tag `vX.Y.Z`**，tag 打在 `main` 上，打完不移动、不删除。
- 后端 `pom.xml`（`0.1.0-SNAPSHOT`）、前端 `package.json`（`0.1.0`）、镜像 tag 三处版本保持一致，发版提交里一并改。

### 4.2 每次发版必须有的东西

| 项 | 要求 |
|---|---|
| tag | `vX.Y.Z` |
| 发布说明 | 新增/修复/变更；**是否含数据库迁移（列出 V 号）**；**是否有新增/变更配置项**；**是否需要手动触发抽取**；是否可回滚 |
| 部署包 | 见 5 |
| 验收记录 | 见 6 |

### 4.3 回滚

- 升级包回滚 = 用上一版的 `jar/` + `static/` 覆盖回去，重启。
- **含数据库迁移的版本不能直接回滚 jar**（Flyway 已把库升上去）：发布说明里必须写明"回滚前需先备份统计库"，统计库可由源库重新抽取，所以以备份 + 重抽为兜底。

## 5. 部署包标准

### 5.1 两种包

| 类型 | 文件名 | 内容 | 何时用 |
|---|---|---|---|
| 完整包 | `district360-docker-<版本>-<日期>.tar.gz` | 镜像、jar、前端、配置模板、`.env`、`start.sh`、README | 新环境首次部署、镜像/基础环境变化 |
| 升级包 | `district360-upgrade-<版本>-<日期>.tar.gz` | 仅 `jar/` + `static/` | 日常升级，**不覆盖 `config/` 和 `.env`** |

### 5.2 包内必须包含

- `VERSION` 文件：版本号、git commit 短 hash、构建时间、构建人/机器。
- 旁边附 `SHA256SUMS`（包本身及包内 jar 的校验值）；交付时随包一起给，部署方先校验再安装。
- 升级包额外带 `UPGRADE.md`：本次发布说明（含迁移、新配置项、是否要触发抽取）。

### 5.3 包内禁止出现

- 开发库的地址、账号、密码（现有脚本已用 `zip -d` 从 jar 里剔除 `application-local.yml`，**出包后必须检查**：`unzip -l district360.jar | grep local` 应无结果）。
- `.git`、源码、`node_modules`、`.env.local`、`.DS_Store`、`._*`。
- 任何真实环境的配置值；`config/application-prod.yml` 只能是占位模板。

### 5.4 构建环境（出包同事）

- 在**干净检出的 tag** 上构建（`git clone` + `git checkout vX.Y.Z`），不要在有未提交改动的工作区出包。
- 工具版本固定：JDK 17、Maven 3.9.x、Node 20+（前端用 `npm ci`）。
- 镜像为 `x86_64`（`eclipse-temurin:17-jre-jammy`）；目标是 ARM 时另做镜像。
- 构建脚本：`deploy/docker/build-package.sh`。

### 5.5 出包验收（部署前必做）

1. `sha256sum -c SHA256SUMS` 通过。
2. 在**测试环境**用完整包或升级包实际装一遍，不是只解压看看。
3. `docker ps` 显示 `healthy`；`GET /<二级路由>/api/v1/meta` 返回正常，抽取状态成功。
4. 打开页面：地图出区边界、点区能出右侧面板、悬浮能看到指标来源。
5. 日志里无 `ERROR`（`logs/district360.log`）。
6. 通过后才可交付给正式环境。

## 7. 常见问题速查

| 现象 | 去哪看 |
|---|---|
| 页面区块显示 `NaN` / "没有查询到数据" | `GET /api/v1/meta` 看各源状态；`stat.etl_job_log` |
| 升级后新字段没有值 | 迁移只加列时需手动触发抽取，见部署 README |
| 升级后启动报字段不存在 | 先在源库跑 `deploy/docker/check-makani-columns.sql` |
| 容器 unhealthy | 数据库连不上也会 unhealthy（健康检查会查统计库），看 `logs/district360.log` |
| 换二级路由 | 只改 `.env` 的 `D360_CONTEXT_PATH` 并 `./start.sh`，不用重打前端 |
