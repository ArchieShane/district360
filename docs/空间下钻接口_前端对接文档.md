# District 360 V1.0 · 空间区划下钻接口 · 前端对接文档

> 适用：按产品原型 V1.0 做「酋长国 → 市政 → 区域 → 社区 → 地块 → 建筑 → 楼层 → 单元」逐级下钻的前端。
> 文中示例均取自 109 线上环境的真实返回（2026-11-25，数据源为 ODS mock 库 makani_1119），为便于阅读做了截短（`…`）。
> 参考实现：仓库 `frontend-360/`（Vue 3 + MapLibre），`src/api.ts` 是完整的 TypeScript 类型与请求封装。

---

## 1. 基础约定

### 1.1 地址

| 环境 | 地址 |
|---|---|
| 109 线上 | `http://10.255.254.109:8360/district360/api/v2/space` |
| 本地后端 | `http://localhost:8080/api/v2/space`（端口以本地启动参数为准） |

- **后端没有开启跨域（CORS）**。前端页面要和接口同源：开发时用开发服务器代理（Vite 示例见 `frontend-360/vite.config.ts`：`/api` 代理到后端），部署时页面和接口挂在同一个域名 / 二级路由下。
- 建议前端用**相对路径** `api/v2/space/...` 发请求（不带开头的 `/`），页面挂在哪个二级路由下接口就跟到哪里。
- 全部是 `GET`、只读，不需要鉴权。

### 1.2 统一返回体（JSON 接口）

```json
{ "code": 0, "message": "ok", "data": { … } }
```

| code | HTTP | 含义 |
|---|---|---|
| `0` | 200 | 成功 |
| `400` | 400 | 参数不对，例如层级名写错、该层级不支持这个图层 |
| `404` | 404 | 编码不存在 |
| `500` | 500 | 服务器内部错误 |

```json
{"code":400,"message":"未知的层级: x（emirate / municipality / district / community / plot / building / floor / unit）","data":null}
{"code":404,"message":"没有这个district: NOPE","data":null}
```

**地图图层接口（`*.geojson`）不包这一层**，直接返回 GeoJSON（`Content-Type: application/geo+json`）。

### 1.3 数据约定

- 坐标：**EPSG:4326 经纬度**，`[经度, 纬度]`。
- 面积：`*Sqm` 为平方米，`*Km2` 为平方公里；高度 / 标高：`*M` 为米。
- **值为空的字段不返回**（`info` 和列表项里），前端按「没有该字段 = 空」处理。
- 数值可能是整数也可能带小数，统一按 `number` 处理。
- 名称：`name` 是英文或编号拼出来的显示名（如 `Plot 4b`、`F2-2`），`nameAr` 只有市政、区域、社区有。

## 2. 层级与编码

页面状态只需要「当前层级 `level` + 编码 `key`」两个值，建议记在地址栏（如 `#/building/udm-9358149`），可分享、可前进后退。

| level | 中文 | key 规则 | key 示例 | 下一级 | 可用图层 |
|---|---|---|---|---|---|
| `emirate` | 酋长国 | 固定 `AD` | `AD` | municipality | `municipalities`、`districts` |
| `municipality` | 市政 | 市政编码 | `ADM` / `AAM` / `WRM` | district | `districts` |
| `district` | 区域 | `<市政>-<区编号>` | `ADM-48` | community | `communities`、`plots`、`buildings` |
| `community` | 社区 | `<市政>-<区编号>-<社区编号>` | `ADM-1300-710` | plot | `plots`、`buildings` |
| `plot` | 地块 | GIS ID（gisid） | `10004344286` | building | `buildings` |
| `building` | 建筑 | `udm-<内部编号>`；只有 BDMS 分层数据的为 `bdms-<市政>-<编号>` | `udm-9358149` | floor | `floors`、`units` |
| `floor` | 楼层 | `<市政>-<楼层编号>` | `ADM-611142` | unit | `units` |
| `unit` | 单元 | `<市政>-<单元编号>` | `ADM-1227944` | —（最末级） | — |

- 编码是字符串，**不要当数字处理**（地块 gisid 有 11 位，可能超出前端数值精度，也可能带前导零）。
- 编码里可能有 `-`，放进 URL 路径时用 `encodeURIComponent`。
- 不要自己拼编码：一律从接口返回的 `key` 取。
- 市政编码：`ADM` 阿布扎比市政、`AAM` 艾因市政、`WRM` 达夫拉地区市政。
- 下钻起点：`emirate / AD`。

## 3. 接口一览

| # | 接口 | 用途 |
|---|---|---|
| 1 | `GET /nodes/{level}/{key}` | 节点视图：右侧 360 面板的标题、上级路径、计数、分组统计、属性，一次取齐 |
| 2 | `GET /nodes/{level}/{key}/children` | 下一级列表（分页、关键字），下拉选择、列表页签 |
| 3 | `GET /nodes/{level}/{key}/layers/{layer}.geojson` | 地图图层 |
| 4 | `GET /search` | 搜索区域、社区、地块、建筑 |
| 5 | `GET /meta` | 主题表行数、最近一次同步结果（「数据」页签） |

以下路径都省略前缀 `…/api/v2/space`。

## 4. 节点视图 `GET /nodes/{level}/{key}`

### 请求

| 参数 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `level` | 路径 | 是 | 见第 2 节 |
| `key` | 路径 | 是 | 见第 2 节 |

### 返回 `data`

| 字段 | 类型 | 说明 |
|---|---|---|
| `level` / `key` | string | 当前节点 |
| `name` | string | 显示名 |
| `nameAr` | string \| null | 阿拉伯文名（只有市政、区域、社区有） |
| `path` | `{level,key,name}[]` | 上级链，从酋长国开始，**不含自己**。面包屑、层级条直接用 |
| `childLevel` | string \| null | 下一级层级；单元为 `null` |
| `childCount` | number | 下一级个数（地块不含已注销） |
| `bbox` | `[minLon, minLat, maxLon, maxLat]` | 外包框，地图定位用（如 MapLibre `fitBounds`） |
| `center` | `[lon, lat]` | 面内一点，放标签 / 标注用 |
| `geometry` | GeoJSON Geometry \| null | 节点自身的形状，地图上描边高亮用；区域及以上已简化；酋长国为 `null` |
| `info` | object | 本层级的属性，**字段随层级不同**，见 4.1 |
| `stat` | object | 计数汇总，见 4.2 |
| `breakdowns` | object | 分组统计，见 4.3 |
| `layers` | string[] | 本层级可请求的地图图层 |

### 4.1 `info` 字段（按层级）

所有下级节点都带全部上级编码：`municipalityCode`、`districtKey`、`communityKey`、`plotKey`、`buildingKey`、`floorKey`（有就返回）。

| 层级 | 字段 |
|---|---|
| municipality | `municipalityId`、`areaKm2` |
| district | `districtId`、`popularNameEn`、`population`、`areaKm2` |
| community | `communityId`、`popularNameEn`、`compositeNameEn`、`areaKm2` |
| plot | `gisid`、`plotId`、`plotNumber`、`elmsPlotId`、`areaSqm`、`plannedAreaSqm`、`constructionStatus`、`serviceStatus`、`planningStatus`、`plotStatus`、`primaryUse`、`parentLandUse`、`landUse`、`secondaryUse`、`ownershipType`、`allocationStatus`、`investmentName`、`devcode`、`devcodeCategory`、`devcodeFar`（允许容积率，**文本**）、`devcodeMaxGfa`（可建面积 m²）、`maxHeights`、`zoneTpss`、`sectorTpss`、`projectId`、`permitLastType`、`permitLastDate`、`cancelDate`、`srcDistrictEn`、`srcCommunityEn`、`modifiedDate` |
| building | `source`、`buildingId`、`buildingInternalId`、`bdmsBuildingId`、`gisid`、`physicalStatus`、`primaryUsageType`、`primaryUse`、`secondaryUsageType`、`floorsCount`（登记层数）、`heightM`、`completionDate`、`demolitionDate`、`startDate`、`permitId`、`constructionSiteId`、`isBdms`、`bdmsFloors`、`bdmsUnits`、`footprintSqm` |
| floor | `source`、`floorId`、`bdmsBuildingId`、`floorNumber`、`floorSeq`（自下而上序号）、`baseHeightM`、`floorHeightM`、`areaSqm`、`buildingStatus`、`plotPrimaryUse`、`buildingFloors` |
| unit | `unitId`、`unitNumber`、`unitType`、`usageType`、`classification`、`category`、`areaSqm`、`bedrooms`、`bathrooms`、`balconyAreaSqm`、`floorNumber`、`baseHeightM`、`floorHeightM`、`buildingStatus` |

日期字段为 `YYYY-MM-DD` 字符串。字段中文名可直接参考 `frontend-360/src/labels.ts` 的 `INFO_LABEL`。

**`source`（数据来源）取值**，页面上建议对推导数据加标注（原型里的「推导数据」标签）：

| 层级 | 取值 | 含义 |
|---|---|---|
| building | `udm` | 现状建筑台账 |
| building | `bdms` | 台账里没有、由 BDMS 楼层外包面推导出的建筑 |
| floor | `bdms_floors` | BDMS 楼层表 |
| floor | `bdms_units` | 楼层表里没有、由单元推导的楼层 |

### 4.2 `stat` 计数

| 字段 | 说明 | 出现层级 |
|---|---|---|
| `municipalities`、`districts` | 市政数、区域数 | emirate（`districts` 也出现在 municipality） |
| `communities` | 社区数 | emirate ~ district |
| `plots` | 地块数（不含已注销） | emirate ~ community |
| `plotsConstructed` / `plotsUnderConstruction` / `plotsNotConstructed` | 已建 / 在建 / 空置地块数 | 同上 |
| `plotsAreaSqm` | 地块面积合计 | 同上 |
| `buildings` / `buildingsUnderConstruction` | 建筑数 / 在建建筑数 | emirate ~ plot |
| `floors` / `units` | BDMS 楼层数 / 单元数 | emirate ~ building |
| `unitsAreaSqm` | 单元面积合计 | emirate ~ floor |
| `unitsWithBedrooms` / `bedrooms` | 有卧室的单元数 / 卧室总数 | floor |

- 不适用的字段返回 `0`（如建筑节点的 `plots`）。建成率 = `plotsConstructed / plots`，前端自己算。
- 楼层、单元只覆盖有 BDMS 分层数据的建筑。

### 4.3 `breakdowns` 分组统计

每组是 `[{ k, n, area }]`：`k` 取值，`n` 个数，`area` 面积（m²），按 `n` 降序，最多 24 项。

| 键 | 含义 | 面积口径 | 出现层级 |
|---|---|---|---|
| `plotStatus` | 地块建设状态：`Constructed` / `Under Construction` / `Not Constructed` / `Unknown` | 地块面积 | emirate ~ community |
| `landUse` | 地块主要用途（Residential、Commercial…） | 地块面积 | emirate ~ community |
| `buildingUse` | 建筑主要用途 | **固定为 0**，只看 `n` | emirate ~ plot |
| `buildingStatus` | 建筑状态（existing、As Planned…） | 固定为 0 | plot |
| `unitClass` | 单元户型（Apartment、Villa…） | 单元面积 | emirate ~ floor |
| `unitType` | 单元类型 | 单元面积 | building |
| `bedrooms` | 卧室数（`"0"`、`"1"`…，未知为 `"—"`） | 单元面积 | building、floor |

地块状态的中文与颜色建议与原型一致：

| k | 中文 | 颜色 |
|---|---|---|
| `Constructed` | 已建 | `#3D6DF2` |
| `Under Construction` | 在建 | `#F0914A` |
| `Not Constructed` | 空置 | `#62D36A` |

## 5. 下一级列表 `GET /nodes/{level}/{key}/children`

### 请求

| 参数 | 位置 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `level`、`key` | 路径 | 是 | | 父节点 |
| `page` | query | 否 | `0` | 页码，从 0 开始 |
| `size` | query | 否 | `50` | 每页条数，最大 500 |
| `q` | query | 否 | | 关键字，见下表 |

### 返回 `data`

```json
{ "items": [ … ], "page": 0, "size": 2, "total": 55, "hasMore": true }
```

### 各层级的列表项

每项都有 `key`、`name`、`sub`（副标题，可能没有），其余字段随下一级层级不同：

| 下一级 | 字段 | `q` 匹配 | 排序 |
|---|---|---|---|
| municipality | `areaKm2`、`districts`、`communities`、`plots`、`buildings`、`units` | 名称、编码 | 名称 |
| district | `areaKm2`、`population`、`communities`、`plots`、`plotsConstructed`、`buildings`、`units` | 英文名、阿拉伯文名（模糊） | 名称 |
| community | `areaKm2`、`plots`、`plotsConstructed`、`buildings`、`units` | 名称（模糊）、社区编号 | 名称 |
| plot | `areaSqm`、`status`（建设状态）、`use`（用途）、`buildings`、`units` | 地块号（模糊）、gisid、地块编号 | 地块号 |
| building | `status`、`source`、`floorsCount`、`floors`、`units`、`heightM` | 名称（模糊）、建筑编号 | 单元数、高度降序 |
| floor | `seq`、`baseHeightM`、`floorHeightM`、`areaSqm`、`units` | 楼层号 | 自下而上 |
| unit | `type`、`areaSqm`、`bedrooms`、`bathrooms`、`floorKey` | 单元号、户型 | 楼层、单元号 |

用法建议：
- 面包屑下拉（切换同级）：请求**上一级**的 children，`size=200`，输入框里的文字传 `q`，防抖 250 ms。
- 列表页签：`size=50`，`hasMore` 为 `true` 时显示「加载更多」，`page + 1`。
- 社区下的地块可能上千块，**不要一次取全部**。

## 6. 地图图层 `GET /nodes/{level}/{key}/layers/{layer}.geojson`

返回 GeoJSON `FeatureCollection`（不包 `code / data`）。可以直接作为 MapLibre 的 GeoJSON 数据源。HTTP 缓存 5 分钟。

| 参数 | 说明 |
|---|---|
| `level`、`key` | 范围节点 |
| `layer` | 必须在该节点的 `layers` 里，否则返回 400（统一返回体） |

### 图层与要素属性

所有要素都有 `key`、`name`、`level`（点击要素后用 `level` + `key` 下钻）。

| layer | 范围 | 几何 | 其他属性 | 上限 |
|---|---|---|---|---|
| `municipalities` | 全部市政 | 面（已简化） | `cx`、`cy`（标签点） | 10 |
| `districts` | 酋长国或某市政下的区域 | 面（已简化） | `m`（市政编码）、`cx`、`cy`、`plots`、`buildings`、`units`、`built`（建成率 %，可能缺） | 500 |
| `communities` | 区域下的社区 | 面（已简化） | `cx`、`cy`、`plots`、`buildings`、`units`、`built` | 5,000 |
| `plots` | 区域 / 社区下的地块（不含已注销） | 面 | `s`（建设状态）、`u`（用途）、`area`（m²） | 30,000 |
| `buildings` | 区域 / 社区 / 地块下的建筑 | 面 | `src`（来源 udm / bdms）、`st`（状态）、`u`（用途）、`fd`（是否有 BDMS 分层）、`h`（拉伸高度 m） | 30,000 |
| `floors` | 建筑的楼层 | 面 | `seq`、`b`（底标高 m）、`t`（顶标高 m） | 2,000 |
| `units` | 建筑或楼层的单元 | 面 | `floor`（楼层 key）、`c`（户型）、`b`、`t` | 20,000 |

- `h`：有登记高度用高度，否则用层数 × 3.5 m，都没有时为 6 m。
- `b` / `t` 直接对应 MapLibre `fill-extrusion-base` / `fill-extrusion-height`，楼层、单元可以按真实标高叠成 3D。
- 要素 `id` 是本次返回里的序号，**不是业务编码**，不要用它关联数据。

| 请求 | 大约大小 |
|---|---|
| `emirate/AD/layers/districts` | 0.3 MB |
| 一个社区的 `plots` / `buildings` | 几十 KB ~ 1 MB |

### 各层级建议加载的图层（`frontend-360` 的做法）

| 当前层级 | 加载 |
|---|---|
| emirate / municipality | 当前节点的 `districts`（按 `built` 着色，`cx` / `cy` 放名称标签） |
| district | `communities` + `plots` + `buildings` |
| community | `plots`（按 `s` 着色）+ `buildings`（3D 拉伸 `h`） |
| plot | 所在社区的 `plots`（背景）+ 本地块的 `buildings` |
| building | 所在地块的 `buildings`（压暗、去掉本楼）+ 本楼的 `floors`（半透明）+ `units`（按 `c` 着色） |
| floor | 所在建筑的 `floors` + 本层的 `units` |
| unit | 所在建筑的 `floors` + 所在楼层的 `units`，选中单元高亮 |

当前节点自身用 `geometry` 描边。上级节点的 `key` 从 `path` 里取。

## 6A. 开发建设页签 `GET /nodes/{level}/{key}/dev`

任意层级都可请求。建筑 / 楼层 / 单元按**所在地块**统计（规划管控在地块上），返回的 `scope` 告诉前端实际统计的范围；所在建筑没有地块时 `scope` 为 `null`，其余字段不返回。

  "masterPlans":[{"projectId":"1099.0","projectNo":"1510","name":"Reem Island Master Plan","stage":"Concept","approvalYear":2015,
                  "developer":"Bunya (Aldar, Tamouh, Reem Developers)","level":"Level 0","areaSqm":891963,"cx":…,"cy":…,
                  "plots":0,"plotsBuilt":0}, …],
  "sites":[{"siteId":"4285","areaSqm":68934,"buildings":0,"plotKey":…,"cx":…,"cy":…}, …],

| 字段 | 说明 |
|---|---|
| `summary.masterPlans` | 范围内的总规项目数（地块范围 = 该地块上的总规地块所属项目） |
| `summary.mpPlots` / `mpPlotsLinked` / `mpPlotsBuilt` | 总规地块数 / 能对上地块的 / 所在地块已建的。**总规实现率 = mpPlotsBuilt / mpPlotsLinked**，前端自己算 |
| `summary.plannedGfa` / `plannedUnits` / `plannedPopulation` / `plannedHotelRooms` | 规划建筑面积 m²、住宅单元、人口、酒店房间 |
| `summary.sites` / `siteBuildings` / `siteAreaSqm` | 在建工地数、工地上的在建建筑数、工地面积 |

地图图层：区域、社区可请求 `masterplans`（总规项目面，属性 `stage`、`year`、`dev`），区域、社区、地块可请求 `sites`（在建工地面，属性 `b` 在建建筑数、`area`）。这两类要素的 `level` 是 `masterplan` / `site`，**不是下钻层级，点击不要跳转**。

资本项目、建设许可、竣工 / 维修 / 拆除还没有源数据，`GET /meta` 里对应表没有 `extractor`，按「待接入」显示。

## 6C. 城市运行页签 `GET /nodes/{level}/{key}/ops`

路灯、公交站是区域设施，没有地块属性：**地块 / 建筑 / 楼层 / 单元按所在社区统计**（`scope.level = community`）；没有社区时 `scope` 为 `null`。

```json
{"scope":{"level":"district","key":"ADM-48"},
 "summary":{"lights":3595,"lamps":6761,"lightsInService":3484,"lightsOutOfService":26,"busStops":90,"busPlatforms":145},
 "lightsByStatus":[{"k":"In Service","n":3484,"lamps":6613},{"k":"Proposed","n":47,"lamps":55}, …],
 "lightsByLampType":[{"k":"HPS","n":3246,…},{"k":"MH","n":341,…}, …],
 "busStops":[{"stopId":"13080","name":"Al Ain Rd / Abu Dhabi University","nameAr":"…","platforms":1,"codes":"13080B","cx":54.559,"cy":…}, …]}
```

| 字段 | 说明 |
|---|---|
| `summary.lights` / `lamps` | 路灯点数 / 灯盏数（一个点可有多盏）。在用率 = `lightsInService / lights`，前端自己算 |
| `lightsByStatus[].k` | `In Service` 在用、`Out Of Service` 停用、`UnderConst` 在建、`Proposed` 规划、`Abandon` 废弃 |
| `lightsByLampType[].k` | `HPS` 高压钠灯、`MH` 金属卤化物灯、`MV` 汞灯、`LPS` 低压钠灯、`FLUO` 荧光灯 |

地图图层：区域、社区可请求 `busstops`（站台点，属性 `code`、`stop`）和 `streetlights`（路灯点，属性 `st` 状态、`n` 灯盏数）。要素 `level` 为 `busstop` / `streetlight`，**不是下钻层级，点击不要跳转**。建筑最多的区域约 3,600 个路灯点（0.8 MB）。

居民诉求、道路事故、视觉违规、违规处罚、住宅占用还没有源数据，原因见 `GET /meta` 的 `tables[].note`。

## 7. 搜索 `GET /search`

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `q` | 是 | | 至少 2 个字符，少于 2 个返回空数组 |
| `limit` | 否 | `8` | 每类最多条数，最大 20 |

## 9. 典型交互流程

```
打开页面（#/emirate/AD）
  ├─ GET /nodes/emirate/AD                       → 面板
  └─ GET /nodes/emirate/AD/layers/districts      → 地图区域面 + 名称标签
点击地图上的区域（要素属性 level=district, key=ADM-48）
  ├─ 地址栏改为 #/district/ADM-48
  ├─ GET /nodes/district/ADM-48                  → 面板、fitBounds(bbox)
  └─ GET …/layers/communities、plots、buildings  → 地图
点击社区 → 地块 → 建筑（同上）
在建筑面板里点楼层（来自 GET /nodes/building/{key}/children）
  ├─ GET /nodes/floor/ADM-611142
  └─ GET /nodes/building/{建筑key}/layers/floors + /nodes/floor/ADM-611142/layers/units
点击单元 → GET /nodes/unit/ADM-1227944
点击面包屑上的某一级 → 直接跳到 path 里那一级的 level + key
```

切换节点时，请**取消上一次还没返回的请求**（`AbortController`），避免快速点击时旧结果覆盖新结果。
