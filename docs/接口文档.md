## 1. 基础约定

### 1.1 访问地址

所有接口前缀为 `/api/v1`，**整体挂在二级路由（context-path）下**：

```
http(s)://<host>[:<port>]<context-path>/api/v1/...
```

| 环境 | Base URL | 示例 |
|---|---|---|
| **109 服务器（本文档默认）** | `http://10.255.254.109:8360/district360` | `http://10.255.254.109:8360/district360/api/v1/meta` |
| 本地开发 | `http://localhost:8080`（context-path 为空） | `http://localhost:8080/api/v1/meta` |
| 生产（经上层 Nginx） | `https://<域名>/district360` | `https://<域名>/district360/api/v1/meta` |

`context-path` 由环境变量 `D360_CONTEXT_PATH` 决定（部署目录 `.env`）。**前端页面和接口同端口**：页面在 `<context-path>/`，接口在 `<context-path>/api/v1/`，前端用相对路径，不需要关心前缀。

经过上层 Nginx 代理时必须**原样保留前缀**，`proxy_pass` 不要带末尾 `/` 或路径，详见 `deploy/docker/README.md`。

下文的路径都省略 `<context-path>`，写成 `/api/v1/...`。

### 1.2 统一返回体（JSON 接口）

除「区边界 GeoJSON」和「矢量瓦片」外，所有接口返回统一格式：

```json
{ "code": 0, "message": "ok", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 成功；失败时与 HTTP 状态码一致（400 / 401 / 403 / 404 / 500） |
| `message` | string | 成功为 `ok`；失败为错误说明（中文） |
| `data` | object / array / null | 业务数据；失败时为 `null` |

**判断成功**：HTTP 状态码为 200 且 `code == 0`。

### 1.3 数据类型约定

| 类型 | 格式 | 示例 |
|---|---|---|
| 日期 | `yyyy-MM-dd` | `"2026-11-15"` |
| 年月 | `yyyy-MM` | `"2026-10"` |
| 时间戳 | ISO-8601，带时区 | `"2026-11-21T16:33:40.367185Z"` |
| 坐标 | `[经度, 纬度]`，EPSG:4326 | `[54.4115, 24.4789]` |
| 外包框 | `[minLon, minLat, maxLon, maxLat]` | `[53.595, 24.093, 53.989, 24.351]` |
| 小数 | JSON number | `86.59` |
| 缺失值 | `null` | 数据源没有数据时，数值字段为 `null`，不是 0 |

### 1.4 区编码 `code`

区名跨市政会重复（如 ADM 和 AAM 都有 AL BATEEN），所以区编码 = **市政 + 区名的小写短横线形式**：

| 示例 | 含义 |
|---|---|
| `adm-al-reem-island` | ADM 市政的 Al Reem Island |
| `adm-al-adlah` | ADM 市政的 Al Adlah |

目前共 **216 个区**（ADM 101、AAM 69、WRM 46）。区列表以数据库为准，不是写死的配置；编码请从 `/districts` 或 `/map/districts.geojson` 取，不要自己拼。

## 2. 枚举与状态

### 2.1 区块状态 `status`

概览中每个区块（宜居、土地、房地产、公共设施、公园）都有 `status`，前端据此决定显示数值、标记还是占位：

| 值 | 含义 | 前端表现 |
|---|---|---|
| `ok` | 有数据，正常 | 显示数值 |
| `sample` | 统计库里还是样例数据 | 显示数值并标「样例数值」 |
| `not_assessed` | 不在宜居评估范围（仅宜居得分） | 显示「不在宜居评估范围」，得分字段均为 `null`；公园数据仍照常 |
| `unavailable` | 没有查询到数据（数据源未接入、还没抽取，或该区在源库里没有数据） | 显示完整布局，数值显示 `NaN`，标题标「没有查询到数据」 |

**注意**：`status` 与「数值是否为 null」是两回事。`ok` 的区块里个别字段仍可能为 `null`（例如某区没有同比基数），前端按 `null` 显示 `NaN` 即可。

### 2.2 设施类别 `category`

`school`（学校）、`medical`（医疗）、`mosque`（清真寺）。

### 2.3 地块建设状态

地块瓦片和概览里的 `plotStatus` 使用：

| 值 | 含义 |
|---|---|
| `constructed` | 已建成 |
| `under_construction` | 在建 |
| `vacant_serviced` | 空置·已通市政（有配套） |
| `vacant_unserviced` | 空置·未通市政 |
| `other` | 其他（仅瓦片属性里出现） |

### 2.4 土地利用类别 `key`

`residential`（居住）、`commercial`（商业）、`community`（社区设施）、`open_space`（开放空间）、`other`（公用与其他，兜底类别）。类别、顺序、归类规则由配置 `d360.land-use.groups` 决定，**以接口返回为准**，前端不要写死。

### 2.5 数据源 `source`

`makani`、`liveability`、`adrec`。

## 3. 接口一览

| # | 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|---|
| 1 | GET | `/api/v1/districts` | 区列表（分页、搜索） | 无 |
| 2 | GET | `/api/v1/districts/{code}/overview` | 区概览（右侧面板） | 无 |
| 3 | GET | `/api/v1/districts/{code}/facilities/{category}` | 某区公共设施列表 | 无 |
| 4 | GET | `/api/v1/meta` | 数据源状态 | 无 |
| 5 | GET | `/api/v1/lineage` | 指标血缘 | 无 |
| 6 | GET | `/api/v1/map/districts.geojson` | 全部区边界 | 无 |
| 7 | GET | `/api/v1/map/tiles/buildings/{z}/{x}/{y}.pbf` | 建筑体块矢量瓦片 | 无 |
| 8 | GET | `/api/v1/map/tiles/plots/{z}/{x}/{y}.pbf` | 地块矢量瓦片 | 无 |
| 9 | POST | `/api/v1/admin/etl/{source}` | 手动触发抽取 | `X-Admin-Token` |

所有业务接口**只读统计库**，不会实时查询 makani / 宜居 / ADREC 源库，所以某个源慢了、断了、还没接入，页面照常显示上次抽取的结果。

## 4. 区列表 `GET /districts`

左侧列表分页加载（滚动到底加载下一页），支持搜索。按 `sortNo`（区名顺序）排序。

### 请求参数（Query）

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `page` | int | 否 | `0` | 页码，从 0 开始；小于 0 按 0 处理 |
| `size` | int | 否 | `30` | 每页条数，**范围 1~100**，超出自动截断 |
| `q` | string | 否 | — | 搜索词，前后空格会去掉，空串视为不搜索 |

**`q` 的匹配规则**（大小写不敏感）：

- 英文名、makani 区名、阿语名：**包含**匹配（`ILIKE '%q%'`）；
- 市政（`ADM` / `AAM` / `WRM`）：**整词相等**匹配，不是包含。

### 响应 `data`

| 字段 | 类型 | 说明 |
|---|---|---|
| `items` | array | 当前页的区，见下表 |
| `page` | int | 当前页码 |
| `size` | int | 实际使用的每页条数（截断后） |
| `total` | int | 满足条件的区总数 |
| `hasMore` | boolean | 是否还有下一页 |

`items[]` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 区编码 |
| `nameEn` | string | 英文名 |
| `nameAr` | string | 阿语名 |
| `sortNo` | int | 排序号（从 1 开始） |
| `municipality` | string | 市政：`ADM` / `AAM` / `WRM` |
| `makaniDistrictId` | int | makani 区 ID |
| `centroid` | `[lon, lat]` / null | 区中心点 |
| `bbox` | `[minLon, minLat, maxLon, maxLat]` / null | 外包框 |
| `areaKm2` | number / null | 面积（km²，3 位小数）；makani 未抽取时为 null |
| `liveabilityScore` | number / null | 宜居得分「目前」；**不在评估范围、或没有数据时为 null** |
| `liveabilityStatus` | string | `ok` / `sample` / `not_assessed` / `unavailable`，见 2.1 |

### 示例

```
GET http://10.255.254.109:8360/district360/api/v1/districts?page=0&size=2
GET http://10.255.254.109:8360/district360/api/v1/districts?q=reem
GET http://10.255.254.109:8360/district360/api/v1/districts?q=AAM&size=50
```

```json
{
  "code": 0,
  "message": "ok",
  "data": {

      {

        "sortNo": 1,

        "bbox": [53.59538584400008, 24.09349573800006, 53.98908542800007, 24.35079505400006],
```

## 5. 区概览 `GET /districts/{code}/overview`

右侧面板的全部数据：标题 + 宜居、土地与建设、房地产、公共设施。**一次请求取全**，每个区块独立带 `status` 和 `asOf`（数据日期）。摘要文字由前端按模板拼，接口不返回。

### 路径参数

| 参数 | 说明 |
|---|---|
| `code` | 区编码，见 1.4。不存在返回 404 |

### 响应 `data`

```
data
├─ district        标题
├─ liveability     宜居得分
├─ land            土地与建设
├─ realEstate      房地产
└─ facilities      公共设施（含公园）
```

#### `district`（标题）

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` / `nameEn` / `nameAr` | string | 编码、英文名、阿语名 |
| `municipality` | string | `ADM` / `AAM` / `WRM` |
| `makaniDistrictId` | int | makani 区 ID |
| `areaKm2` | number / null | 面积 km² |
| `communities` | int / null | 社区数 |
| `plots` | int / null | 地块数 |

#### `liveability`（宜居得分，来源：宜居库）

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 见 2.1。`not_assessed` 时下面的得分字段全为 null |
| `asOf` | date / null | 数据日期 |
| `existing` | number / null | 得分「现状」（Existing） |
| `current` | number / null | 得分「目前」（Pipeline） |
| `target` | number / null | 得分「目标」（AP50） |
| `gap` | number / null | 目标与目前的差距 = `max(target − current, 0)`，由接口计算 |

#### `land`（土地与建设，来源：makani）

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `ok` / `unavailable` |
| `asOf` | date / null | 数据日期 |
| `plots` | int / null | 地块数 |
| `buildings` | int / null | 建筑数 |
| `buildingsUnderConstruction` | int / null | 在建建筑数 |
| `plotBuiltRatePct` | number / null | 地块建成率 %（已建成 ÷ 地块数，1 位小数） |
| `plotStatus` | object | 地块状态分布，见下 |
| `landUse` | array | 土地利用占比，见下 |

`plotStatus`：`constructed`（已建成）、`underConstruction`（在建）、`vacantServiced`（空置·已通市政）、`vacantUnserviced`（空置·未通市政），均为 int / null。

`landUse[]`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | string | 类别键，见 2.4 |
| `nameZh` / `nameEn` | string | 中英文名 |
| `plotCount` | int | 该类地块数 |
| `pct` | number / null | 占比 %（1 位小数）；该区没有地块时为 null |
| `highlight` | boolean | 是否显示在面板「土地利用」一行（目前只有居住、商业） |
| `fallback` | boolean | 是否为兜底类别（没被任何分组列出的用途都归到这里） |

`landUse` 按配置顺序返回，所有类别都在（计数为 0 也返回）；`status = unavailable` 时为空数组。

#### `realEstate`（房地产，来源：ADREC）

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `ok` / `sample` / `unavailable` |
| `asOf` | date / null | 数据日期（源表最新入库日期） |
| `periodStart` / `periodEnd` | string / null | 统计期起止月，`yyyy-MM`。默认为最近 12 个整月 |
| `salesAedBn` | number / null | 成交额，**单位：十亿迪拉姆（AED Bn）**，2 位小数 |
| `salesYoyPct` | number / null | 成交额同比 %；没有去年同期基数时为 null |
| `transactions` | int / null | 成交笔数（按成交申请去重） |
| `mortgages` | int / null | 抵押数（按抵押合同去重） |
| `avgPriceSqm` | number / null | 均价（AED / m²，按面积加权） |
| `activeLeases` | int / null | 有效租约数（截至租赁快照日期） |
| `monthly` | array | 月度成交笔数，`[{ "month": "2026-01", "transactions": 120 }]`；`unavailable` 时为空数组 |

#### `facilities`（公共设施，来源：makani；`parks` 来源：宜居库）

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `ok` / `unavailable` |
| `asOf` | date / null | 数据日期 |
| `schools` | int / null | 学校数 |
| `medical` | int / null | 医疗设施数 |
| `mosques` | int / null | 清真寺数 |
| `parks` | object | 公园，见下 |

`parks`：`status`（同 2.1，**不受宜居评估范围影响**，不在评估范围的区公园照常展示）、`asOf`、`count`（公园数）、`areaHa`（现有公园面积，公顷）、`gapHa`（公园缺口，公顷，不小于 0），数值字段可为 null。


## 6. 公共设施列表 `GET /districts/{code}/facilities/{category}`

面板里点击学校 / 医疗 / 清真寺的数字展开列表，点击条目后地图定位。**与概览里的计数同一口径**。按英文名（没有则阿语名）不区分大小写排序。

### 路径参数

| 参数 | 说明 |
|---|---|
| `code` | 区编码。不存在返回 404 |
| `category` | `school` / `medical` / `mosque`。其他值返回 400 |

### 响应 `data`：数组

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 源表 `objectid` |
| `category` | string | 设施类别 |
| `nameEn` | string / null | 英文名 |
| `nameAr` | string / null | 阿语名 |
| `subtype` | string / null | 子类型，如学校的 `Private` |
| `location` | `[lon, lat]` | 坐标 |

同一个区没有这类设施时返回空数组 `[]`。

### 示例

```
GET http://10.255.254.109:8360/district360/api/v1/districts/adm-al-reem-island/facilities/school
```

```json
{
  "code": 0, "message": "ok",
  "data": [
    { "id": "480", "category": "school", "nameEn": "Gems World Academy", "nameAr": "أكاديمية جيمس العالمية",
      "subtype": "Private", "location": [54.41148908500003, 24.478923218000034] }
  ]
}
```

## 7. 数据源状态 `GET /meta`

区数量、各数据源的数据日期和最近一次抽取状态。前端用它得到「数据版本」（用于瓦片和边界的缓存参数 `v`，见 14.2），也方便运维核对抽取是否成功。

### 响应 `data`

| 字段 | 类型 | 说明 |
|---|---|---|
| `districtCount` | int | 区数量（216） |
| `blockCount` | int | 页面区块数（固定 4：宜居、土地与建设、房地产、公共设施） |
| `sources` | array | 每个数据源一条 |

`sources[]`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `source` | string | `makani` / `liveability` / `adrec` |
| `enabled` | boolean | 后端是否配置并启用了该源的抽取器 |
| `rowCount` | int | 统计库里该源的行数（有数据的区数） |
| `sourceAsOf` | date / null | 源数据日期 |
| `sample` | boolean | 统计库里是否还是样例数据 |
| `lastStatus` | string / null | 最近一次抽取状态：`success` / `failed` / `running`；从未抽取为 null |
| `lastFinishedAt` | timestamp / null | 最近一次抽取结束时间（UTC） |
| `lastMessage` | string / null | 失败时的原因 |

### 示例

```json
{
  "code": 0, "message": "ok",
  "data": {
    "districtCount": 216, "blockCount": 4,
    "sources": [
```

## 8. 指标血缘 `GET /lineage`

页面上每个数值鼠标悬停（停留约 3 秒）显示的「指标来源」：页面读统计库哪一列、源头是哪个库哪张表、怎么算、对应的 SQL。说明写在 `metric-lineage.yml`，**库名、表名占位符在运行时已按实际配置替换**。

### 响应 `data`

| 字段 | 类型 | 说明 |
|---|---|---|
| `statDb` | string | 统计库库名（页面实际读取的库） |
| `sources` | object | 以 source 为键 |
| `metrics` | object | 以指标键为键（共 30 个，如 `area_km2`、`liv_current`、`re_sales`） |

`sources.<key>`：`nameZh`、`nameEn`、`database`（源库库名）、`implemented`（该源的抽取器是否已启用；`false` 时 SQL 是计划口径）。

`metrics.<key>`：

| 字段 | 说明 |
|---|---|
| `nameZh` / `nameEn` | 指标名 |
| `source` | 所属数据源 |
| `statColumn` | 统计库里的列，如 `stat_district_makani.area_km2` |
| `sourceTables` | 源库表名列表（已按 schema、前缀配置替换） |
| `logicZh` / `logicEn` | 计算口径说明 |
| `sql` | 参考 SQL，含 `:makani_district_id`、`:municipality` 这类**区参数占位符，由前端按选中区替换**，方便复制 |

前端给数值加 `data-m="<指标键>"` 即可接入悬停提示。指标键清单见接口返回。

## 9. 区边界 GeoJSON `GET /map/districts.geojson`

全部区的边界（已简化），地图一次性加载，用于区高亮、标签和悬停。**不使用统一返回体**，直接返回 GeoJSON。

- **Content-Type**：`application/geo+json`
- **坐标系**：EPSG:4326
- **缓存**：`Cache-Control: max-age=600`（10 分钟）。前端用 `?v=<数据版本>` 控制失效，见 14.2。体积较大（约 360 KB，已 gzip）。

### 响应结构

`FeatureCollection`，每个区一个 `Feature`，按 `sortNo` 排序；只返回有边界的区。

| 位置 | 字段 | 说明 |
|---|---|---|
| `feature.id` | int | = `sortNo` |
| `feature.geometry` | Polygon / MultiPolygon | 简化后的区边界，坐标保留 5 位小数 |
| `properties.code` | string | 区编码 |
| `properties.nameEn` / `nameAr` | string | 英文名 / 阿语名 |
| `properties.sortNo` | int | 排序号 |
| `properties.municipality` | string | 市政 |
| `properties.makaniDistrictId` | int | makani 区 ID |
| `properties.areaKm2` | number / null | 面积 km² |
| `properties.liveabilityScore` | number / null | 宜居得分「目前」；不在评估范围时为 null |
| `properties.livInScope` | boolean / null | 是否在宜居评估范围；`null` 表示未知（按在范围内处理） |
| `properties.livSample` | boolean / null | 宜居数据是否为样例 |
| `properties.centroid` | `[lon, lat]` | 中心点 |
| `properties.bbox` | `[minLon, minLat, maxLon, maxLat]` | 外包框 |

## 10. 矢量瓦片

地图选中区后按需加载的 Mapbox Vector Tile（MVT / PBF，4096 分辨率，64 缓冲）。**不使用统一返回体**。

| 项 | 值 |
|---|---|
| 路径 | `/map/tiles/{layer}/{z}/{x}/{y}.pbf`，`layer` 为 `buildings` 或 `plots` |
| 瓦片方案 | XYZ（Web Mercator，`ST_TileEnvelope`） |
| Content-Type | `application/x-protobuf` |
| 缓存 | `Cache-Control: max-age=3600`（1 小时） |
| 空瓦片 | 该瓦片没有要素时返回 **200 且正文为空**（0 字节），不是 404 |

### 参数校验

`z` 取值 0~22；`x`、`y` 取值 0 ~ 2^z − 1。越界返回 **400（无正文）**。

### 图层 `buildings`（建筑体块，用于 3D 挤出）

| 属性 | 类型 | 说明 |
|---|---|---|
| `code` | string | 所属区编码 |
| `height` | number | 建筑高度，用于 3D 挤出（单位沿用 makani 源数据，一般为米） |
| `uc` | boolean | 是否在建 |

建议缩放：`minzoom 12`，`maxzoom 16`。

### 图层 `plots`（地块，选中区后按建设状态高亮）

| 属性 | 类型 | 说明 |
|---|---|---|
| `code` | string | 所属区编码 |
| `plot_id` | string | 地块 ID |
| `status` | string | 建设状态，见 2.3 |
| `use_desc` | string | 用地用途描述（英文，如 `Residential`、`Commercial`） |

建议缩放：`minzoom 10`，`maxzoom 16`。

### 在 MapLibre 里使用

```js
map.addSource('buildings', {
  type: 'vector',
  tiles: [`${base}/api/v1/map/tiles/buildings/{z}/{x}/{y}.pbf?v=${dataVersion}`],
  minzoom: 12, maxzoom: 16
})
// 图层: source-layer = 'buildings'
```

`{base}` 必须是**绝对地址**（MapLibre 在 Worker 里请求瓦片，不能用相对路径），例如用 `new URL('./', location.href).href` 拼出页面所在目录。

## 11. 手动触发抽取 `POST /admin/etl/{source}`

抽取默认每天 **03:00（迪拜时间）** 自动执行，统计表为空时启动后会自动补跑一次 makani。这个接口用于手动触发，**需要口令**。

### 请求

| 项 | 说明 |
|---|---|
| 路径参数 `source` | `makani` / `liveability` / `adrec` / `all`（按 makani → liveability → adrec 顺序依次执行） |
| 请求头 `X-Admin-Token` | 管理口令，需与配置 `d360.admin.token` 一致 |

### 响应 `data`：数组，每个源一条

| 字段 | 类型 | 说明 |
|---|---|---|
| `source` | string | 数据源 |
| `status` | string | `success` / `failed` / `skipped` |
| `rowCount` | int / null | 写入统计库的行数（含月度明细）；失败时为 null |
| `sourceAsOf` | date / null | 数据日期 |
| `durationMs` | int | 耗时（毫秒） |
| `message` | string / null | 失败原因，或跳过原因（如「该数据源正在抽取中」） |

### 行为说明

- **同步执行**：请求会一直等到抽取结束才返回，makani 约 1 分钟，ADREC 取决于数据量（生产约 4 分钟），客户端超时要设够（建议 ≥ 15 分钟）。客户端断开不会终止服务端的抽取。
- **同一数据源不会并发抽取**：已经在抽取时再触发，该源返回 `skipped`。
- **一个源失败不影响其他源**：每个源各自记录成功或失败，失败的源统计库保持上次的结果不变（按源整批替换，单事务）。
- **没有启用的抽取器**（如没配置 ADREC 库）：返回 404。
- 抽取状态可以在 `GET /meta` 的 `lastStatus` 里看到；抽取历史在统计库 `stat.etl_job_log`。

### 示例

```bash
curl -X POST -H "X-Admin-Token: <口令>" http://10.255.254.109:8360/district360/api/v1/admin/etl/all
```

```json
{
  "code": 0, "message": "ok",
  "data": [
    { "source": "makani", "status": "success", "rowCount": 820773, "sourceAsOf": "2026-11-15", "durationMs": 45699, "message": null },
    { "source": "liveability", "status": "success", "rowCount": 216, "sourceAsOf": "2026-10-29", "durationMs": 876, "message": null },
    { "source": "adrec", "status": "success", "rowCount": 988, "sourceAsOf": "2026-11-06", "durationMs": 231224, "message": null }
  ]
}
```

> **安全建议**：这个接口不要通过域名对外暴露，在 Nginx 里拦掉 `/<context-path>/api/v1/admin/`，只在服务器本机用 `127.0.0.1:<端口>` 触发。口令用足够长的随机串。

## 12. 错误码

| HTTP | `code` | 触发场景 | `message` 示例 |
|---|---|---|---|
| 400 | 400 | `facilities` 的 `category` 不支持；其他非法参数 | `不支持的设施类别: bank` |
| 400 | — | 瓦片坐标越界（`z`、`x`、`y`），无正文 | — |
| 401 | 401 | 手动抽取：`X-Admin-Token` 缺失或不正确 | `X-Admin-Token 不正确` |
| 403 | 403 | 手动抽取：服务端没有配置 `d360.admin.token`，接口已禁用 | `未配置 d360.admin.token，手动抽取接口已禁用` |
| 404 | 404 | 区编码不存在；抽取的 `source` 没有启用 | `没有这个区: nope` |
| 404 | 404 | 路径不存在（如 context-path 写错） | `Not found` |
| 500 | 500 | 服务端异常，最常见是统计库连不上 | `服务器内部错误` |

**排查提示**

- 所有接口突然全部 500：看统计库是否可连（日志里是 `Connection refused` 或连接池超时）。
- 页面能打开但接口全是 404：多半是上层 Nginx 把 `/<context-path>` 前缀去掉了，见 1.1。
- 某个区块全是 `NaN` 且 `status = unavailable`：对应数据源还没抽取，或源库里该区没有数据，看 `GET /meta`。

## 13. 缓存与压缩

| 资源 | `Cache-Control` | 说明 |
|---|---|---|
| 区边界 GeoJSON | `max-age=600` | 10 分钟；前端用 `?v=` 数据版本参数换新地址 |
| 矢量瓦片 | `max-age=3600` | 1 小时；同样用 `?v=` |
| 静态页面（js / css / html） | `no-cache` | 每次向服务器确认（未变返回 304），前端更新后不用强刷 |
| 其他 JSON 接口 | 无 | 不缓存 |

**压缩**：服务端对 `application/json`、`application/geo+json`、`application/x-protobuf`、`text/html`、`text/css`、`text/javascript`、`application/javascript`、`image/svg+xml` 开启 gzip，客户端带 `Accept-Encoding: gzip` 即可，上层 Nginx 不需要再压缩。

## 14. 前端接入要点

### 14.1 请求路径

页面挂在 `<context-path>/` 下，前端接口地址用**相对路径** `api/v1/...`（不带开头的 `/`），这样换二级路由名不用重新打包前端。瓦片地址要绝对地址，用页面所在目录拼：

```ts
const BASE = 'api/v1'
const ABS_BASE = () => new URL('./', location.href).href + BASE
```

### 14.2 数据版本 `v`

边界和瓦片都带 `?v=<数据版本>`，数据版本取 `GET /meta` 里 `makani` 的 `lastFinishedAt`（最近一次 makani 抽取完成时间）。**数据重新抽取后地址变化，浏览器不会用到旧缓存**。

### 14.3 典型调用顺序

```
页面加载
 ├─ GET /meta                      → 数据版本 v、各源状态
 ├─ GET /districts?page=0&size=30  → 左侧列表（滚动到底再取下一页）
 ├─ GET /lineage                   → 悬停提示用（页面加载时取一次）
 └─ GET /map/districts.geojson?v=  → 地图区边界

选中一个区（URL 形如 #d=adm-al-reem-island）
 ├─ GET /districts/{code}/overview             → 右侧面板
 ├─ GET /map/tiles/plots/{z}/{x}/{y}.pbf?v=    → 地块高亮（地图自动按需请求）
 ├─ GET /map/tiles/buildings/{z}/{x}/{y}.pbf?v=→ 建筑 3D
 └─ 点击设施数字时：GET /districts/{code}/facilities/{category}
```

### 14.4 状态展示规则

- 数值为 `null` → 显示灰色 `NaN`，不要显示 0。
- 区块 `status = unavailable` → 区块布局照常，标题右侧标「没有查询到数据」。
- 区块 `status = sample` → 标「样例数值」。
- 宜居 `status = not_assessed` → 得分位置显示「不在宜居评估范围」，公园部分仍显示数值。
- 成交额 `salesAedBn` 单位是十亿迪拉姆，展示时按 `AED x.xx Bn` 格式化。

## 附：数据口径与来源

- **统一统计口径**：三个源库都按「统计范围」做空间查询，统计范围 = 每个区的 makani 原始区面（EPSG:4326）。各库的区 ID、区名不一致，但范围一致，所以接口只认区编码。
- **页面只读统计库**（`stat` schema，视图 `v_district_360`），不直接读源库。
- **指标口径以 `GET /lineage` 返回为准**，改取数逻辑时必须同步改 `metric-lineage.yml`。
- 字段对照表 `docs/District360_数据字段对照_*.xlsx` 仅供参考，最终口径以与数据治理确认的为准。
